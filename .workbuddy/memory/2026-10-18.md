## Notepad4 Markdown 实时预览（从零实现并交付）

- 基线：`zufuliu/notepad4` @ `bc6c799`（2026-10-18），克隆到 `upstream-notepad4/`（保持未修改），
  工作副本 `notepad4/`，补丁 `patch/0001-notepad4-markdown-preview.patch`（5 改 +2 新增，+76/−2 行，已 `git apply --check` 验证）。
- 调查结论：Notepad4 **无 DLL 插件机制**（无 NPPM_、无第三方 LoadLibrary、matepath 只是 ShellExecute 外部进程），
  故采用「最小主程序补丁 + 独立预览进程」；单窗口单文档模型（无标签页）。
- 架构：`MarkdownPreview.exe`（md4c → HTML + WebView2 渲染 + 命名管道服务端，ACL 仅当前用户/SYSTEM）

- 安全：md4c `MD_FLAG_NOHTML` 关闭原始 HTML；URL 白名单（http/https/mailto/相对，剔除控制字符防 `java\tscript:`）；
  CSP + 虚拟域 `https://notepad4.mdpreview/*` + 资源路由只允许文档目录内图片；无任何 HTTP 服务。
- 测试：4 阶段共 112 项全绿（86 单元 + e2e 渲染 + 17 进程 IPC + 9 编辑器集成），
  其中 Stage 4 用 `WM_CHAR` 真实键入验证「未保存内容自动刷新」。
- 关键坑（已解决，见 MEMORY.md）：cmd 脚本必须纯 ASCII + CRLF；vcvars 因 reg.exe 被禁无法解析 SDK；
  `HTTPS_PROXY/https_proxy` 重复导致 MSB6001；python 改文件会把 CRLF 变 LF 造成整文件 diff。
- 已知限制：必须替换 Notepad4.exe；locale/*.rc 未同步；GCC/ARM64 未实测；"在浏览器中打开"是一次性快照。

## 追加：支持原始 HTML（GitHub 风格 README）

- 问题：TikTokDownloader/README.md 大量用 `<div align>`、`<img>`、`<details>` 排版，
  而渲染器用 `MD_FLAG_NOHTML` 把 HTML 全转义，页面显示成源码。
- 方案：打开原始 HTML + **C++ 层白名单重建**（`SanitizeHtml()` in MarkdownRenderer.cpp）：
  - 标签白名单 ~70 个；`script/style/iframe/object/embed/svg/math/form` 等连同内容整段丢弃；
  - 属性按标签白名单；`on*`、`srcdoc`、`formaction` 一律不保留；
  - URL 只允许 http/https/mailto/相对/锚点，`src` 额外允许 `data:image/*`；
  - `style` 含 `expression`/`javascript:`/`behavior`/`@import` 时丢弃；
  - `<input>` 仅允许 `type=checkbox`。
- 顺带修两个真 bug：
  1. `ExportSnapshot()` 在持有 `mutex_` 时调用 `LoadAsset()`（内部再锁同一把）→ 递归加锁崩溃；
     拆出 `configMutex_` 专管资源目录/模块句柄。
  2. 页面原本以 `/__app/shell.html` 加载，`./static/a.png` 被解析到 `/__app/static/` 导致图片 404；
     改为从根路径 `/` 加载页面，相对图片正确落到文档目录。
- 调试工具：`mdtest.exe --render <in.md> <out.html>`、`integration_test.exe [file]`。
- 测试：99 项全绿（76 单元 + 23 集成）。

## 追加：图片显示（本地 + 网络）核实与加固

- 核实结论：本地相对路径（`img/a.png`、`./a.png`、子目录）、HTML `<img>`、`https/http` 远程图、
  `data:image/*` 都能显示；`javascript:` / `file:` / 协议相对 URL 被拦。
  截图证据：`build/logs/shot-images.png`（fixture `tests/fixtures/images.md`）。
- 发现并修掉的真问题：
  1. **`loading="lazy"` 不可用**：WebView2 面板被其它窗口遮挡时 Chromium 会无限期推迟懒加载，
     表现为"文字渲染了但图片全空"。已从 `RebuildTag` 去掉，只保留 `decoding="async"`。
  2. **内嵌资源不随源文件更新**：MSBuild 不跟踪 `.rc` 里 RCDATA 引用的文件，只改 CSS/JS 时
     `rc.exe` 不重跑，exe 里仍是旧资源。已给 `ResourceCompile` 加 `AdditionalInputs`，
     列出 4 个 `preview/res/*` 与生成的中文 rc。
  3. **WebView2 控制器创建 0x8007139F**：兼容模式重建时偶发 ERROR_INVALID_STATE 后永久停在错误提示。
     现改为退避重试（600ms 起、每次 +450ms，最多 4 次），成功即清零。
  4. `file:` 绝对路径图片原先放行（靠 CSP 兜底），现改为渲染层直接拒绝并计入 `blockedUrls`。
- 健康检查增强：页面 `notifyHost` 附带 `images:{total,loaded,failed}`；`applyDoc` 记录 `lastChars`，
  避免状态刷新时 `chars` 变成 0；集成测试新增「文档中的本地图片已加载并显示」（等待 `loaded>=1`）。
- 测试工具：`NOTEPAD4_MDPREVIEW_SHOT_DELAY=ms` 让截图前多等，便于人工核对远程图片；
  新增 `scripts/dev/winshot.py`（按窗口截图，无第三方依赖）。
- 结果：107 项全绿（83 单元 + 24 集成）。补丁 11 文件 +4261/−7。
